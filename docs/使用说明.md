# 校园网助手使用说明

## 一、这是做什么的

这是一个运行在 Windows 系统托盘里的校园网断线自动检测与重新认证工具。

- 有线网正常时，它不会访问校园门户。
- 检测到有线断网后，会先确认互联网确实不可用，再重新认证校园网。
- 有线网卡物理断开约 10 秒后，会尝试连接已保存的 `gdei-WiFi-S` 并认证。
- 周日到周四凌晨 `01:00–06:00` 的计划断网时段会完全暂停自动操作。
- 默认无需管理员权限，不需要安装浏览器插件或额外运行库；优先直接认证，只有直连门户失败时才临时调用本机 Chrome 或 Edge。

## 二、第一次使用

1. 双击 `CampusNetGuard.exe` 运行，程序会出现在系统托盘。如果托盘里已经有旧版程序，请先右键选择“退出”，再启动新版。
2. 右键托盘图标，选择“账号设置...”。
3. 填写校园网账号和密码，点击“保存”。
4. 程序会使用当前 Windows 用户的 DPAPI 加密密码，只在本机保存密文，不保存明文密码。
5. 如果需要，可以在同一个设置窗口中关闭或开启“当前用户登录后自动启动”。

程序首次运行默认会开启当前用户的开机启动。可以在托盘菜单的“开机启动”里随时关闭。

如果重复双击程序，也只会保留已经在托盘里运行的一份，不会启动第二个检测程序。

## 三、托盘菜单

- **查看状态**：打开状态窗口，显示有线、无线、互联网、校园环境、计划暂停、最近认证结果和下次重试时间。
- **自动重连**：启用或暂停自动重连。暂停后程序仍然留在托盘，但不会自动检测和认证。
- **立即检测**：立刻执行一次网络检查，适合手动确认状态。
- **有线恢复策略**：选择有线恢复后的处理方式。
  - 稳定 60 秒后自动切回有线（默认）
  - 保留 Wi-Fi，手动切回有线
  - 保持 Wi-Fi，不自动切回
- **账号设置...**：修改校园网账号、密码和开机启动选项。
- **查看日志**：打开当前日志目录。
- **日志保存位置...**：选择新的日志文件夹，并可选择是否移动已有日志。
- **开机启动**：开启或关闭当前用户登录后的自动启动。
- **退出**：完全退出程序。

双击托盘图标也可以打开状态窗口。状态窗口里提供“立即检测”、“暂停/启用自动重连”和“立即恢复有线”按钮。

## 四、断网和暂停规则

程序不会只看“有线网卡是否插着”，而是按下面的逻辑判断：

1. 优先检查真实有线网卡和无线网卡，忽略 UU TAP、ZeroTier、Radmin VPN 等虚拟网卡。
2. 使用 `http://www.msftconnecttest.com/connecttest.txt` 检查互联网，并校验返回内容。
3. 连续两次探测失败、两次之间间隔约 5 秒，才会认为需要重新认证。
4. 计划暂停期间不探测、不认证、不切换 Wi-Fi、不发送通知。

计划暂停时间：

- 周日、周一、周二、周三、周四：凌晨 `01:00–06:00` 暂停。
- 周五、周六：全天不暂停。
- 到 `06:00` 会准点恢复自动检测；如果此时仍处于断网状态，再按正常规则处理。

这样做是为了避免学校计划断网期间反复重试。

## 五、有线断线后的 Wi-Fi 回退

有线网卡持续断开约 10 秒后，程序才会尝试 Wi-Fi 回退；如果只是短暂抖动，不会马上切换。

Wi-Fi 回退的前提：

- 电脑有无线网卡，并且无线网卡、无线开关处于开启状态。
- Windows 已经保存过 `gdei-WiFi-S` 的无线配置。
- 能看到 `gdei-WiFi-S`，或程序能判断当前仍处于校园环境。
- 校园环境判断约有 30 分钟有效期；如果已经回到家里或连接到手机热点，程序会优先保持暂停，避免误切到校园 Wi-Fi。
- 程序不会尝试连接 `gdei-WiFi`，只会使用 `gdei-WiFi-S`。

如果无线网卡或无线开关关闭，程序不会请求管理员权限强制打开，而会在托盘提示你手动开启。

连接 Wi-Fi 成功后，程序会等待获取 IP，再自动发现 Wi-Fi 门户并认证。Wi-Fi 门户地址来自连接后的强制门户跳转，不会猜测 `nasip`。

## 六、认证失败和重试

认证失败会按 `1、5、15、30` 分钟退避重试，并且每小时最多尝试 6 次。

- 账号或密码明确错误时，程序会立即停止自动认证并提示你修改凭据。
- 普通网络故障、门户暂时不可达等问题，会按退避策略继续尝试。
- 如果门户返回内容的格式无法识别，但互联网探测已经恢复，程序会按认证成功处理并记录恢复日志，不再产生误报警告。
- 只有门户实际显示可操作的验证码或二次认证输入框时，程序才会停止自动认证并提示人工处理；门户页面内部的隐藏多语言模板文字不会触发人工验证。
- 门户结构变化、响应无法解析时，会停止本次认证并保留日志，不会无限制快速提交。
- 认证成功后会再次检查互联网，确认网络真正恢复。

新版会先直接访问门户。如果检测到“门户页面为空或未返回登录表单”，程序不会再直接结束，而会自动改用本机 Chrome 或 Edge 临时打开门户，并调用门户页面自己的登录脚本提交认证。浏览器使用独立的临时配置，认证结束后会自动退出并清理。

“门户页面为空或未返回登录表单”表示程序没有取到门户页面，并不等同于“账号或密码错误”。只有门户明确返回凭据错误时，程序才会锁定自动认证并要求你修改账号密码。使用浏览器回退仍失败时，请确认电脑已安装 Chrome 或 Edge，并且该门户地址能在本机浏览器中手动正常打开；随后查看日志里的“浏览器回退”提示。

如果校园门户以后增加验证码、短信验证、动态密码或二次认证等人工步骤，程序会立即停止自动提交并提示你处理，不会反复盲目尝试。

人工完成验证或登录后，可以在托盘菜单或状态窗口点击“立即检测”。如果网络已经恢复，程序会确认联网并解除“需要人工处理”状态。

## 七、数据、密码和日志

程序数据保存在：

`%LOCALAPPDATA%\CampusNetGuard\`

- 设置文件：`%LOCALAPPDATA%\CampusNetGuard\settings.xml`
- 默认日志目录：`%LOCALAPPDATA%\CampusNetGuard\logs`

日志保存位置可以直接在托盘菜单里修改：

1. 右键托盘图标，选择“日志保存位置...”。
2. 选择新的文件夹。
3. 程序会询问是否把已有日志也移动过去。选择“否”只修改以后日志的位置，旧日志保留原处。
4. 修改会立即生效，并保存到设置文件中，下次启动会继续使用该位置。

也可以手动编辑 `%LOCALAPPDATA%\CampusNetGuard\settings.xml` 中的 `<LogDirectory>你的文件夹路径</LogDirectory>`，保存后重启程序。建议优先使用托盘菜单，避免路径写错。

密码只以当前 Windows 用户的 DPAPI 密文保存在设置文件中，不硬编码在程序里，也不会写入日志。日志会对账号进行脱敏。

## 八、开机启动和运行限制

- 开机启动使用当前用户的登录启动项，不创建 Windows 服务。
- 电脑登录后程序才会运行；注销、关机、休眠期间不会工作。
- 程序不会唤醒睡眠或休眠的电脑。
- 移动 `CampusNetGuard.exe` 到新位置后，建议在托盘菜单里重新切换一次“开机启动”，刷新启动路径。
- 程序默认无需管理员权限，也不会强制启用被软件或硬件关闭的无线设备。

## 九、资源占用

程序使用轻量状态机和后台检测线程，没有常驻浏览器；浏览器只在直连门户失败时临时启动。

- 空闲内存通常约 20–40 MB。
- 空闲 CPU 接近 0。
- 默认每 30 秒做一次兜底检查；网络变化事件会触发额外检查。
- 计划暂停结束时会在 `06:00` 准点唤醒一次，随后立即检测。
- 无线网卡未启用或未连接时，不会每 30 秒启动无线查询。
- Wi-Fi 回退、门户认证等操作只在需要时执行。
- 浏览器回退通常只持续几十秒；这段时间 Chrome 或 Edge 可能额外占用约 100–300 MB 内存，认证完成或超时退出后就会释放。

一般不会让电脑明显卡顿。

## 十、当前测试说明

本次实现完成了编译和离线逻辑检查，包括暂停时间边界、周五周六全天运行、门户表单解析、日志脱敏、日志目录切换、校园网关判断、验证码/二次认证时安全停止自动提交，以及浏览器回退能启动、能加载门户并保留门户原生登录脚本的检查。

没有自动使用你的真实账号密码登录门户，也没有自动拔掉你的网线。真实拔线、真实 Wi-Fi 回退和真实门户认证请在你本人在场时手动验证。首次使用如果门户结构、账号字段或认证接口与预期不同，请查看日志并在后续版本中调整。
